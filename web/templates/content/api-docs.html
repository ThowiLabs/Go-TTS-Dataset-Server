Primeros pasos

Desde Clientes registra una instancia (por ejemplo, gpu_t4_01) y copia su token de acceso. Puedes usar hasta cinco instancias o más, cada una con su propio token. Usa siempre HTTPS fuera de la red local.

Configura estas variables en cada cliente:

BASE="https://TU-SERVIDOR"
TOKEN="PEGA_TU_TOKEN_GENERADO"

En las peticiones de la API se usa Authorization: Bearer $TOKEN. Esta credencial identifica al worker sin requerir contraseña del administrador.

1. Comprobar acceso y voz de referencia

Consulta la identidad del cliente y la versión SHA-256 de la referencia. Si no está cargado el audio, este último endpoint devuelve HTTP 404.

curl -H "Authorization: Bearer $TOKEN" "$BASE/api/v1/client/me"

curl -H "Authorization: Bearer $TOKEN" "$BASE/api/v1/reference/meta"

curl -f -H "Authorization: Bearer $TOKEN" \
  "$BASE/api/v1/reference" -o referencia.wav

La respuesta de reference/meta contiene sha256, filename, updated_at y download_url. Comprueba el hash para evitar volver a descargar un audio sin cambios.

2. Reservar un trabajo pendiente

curl -i -X POST "$BASE/api/v1/jobs/claim" \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{}'

La API identifica al cliente por su token y devuelve el primer trabajo pendiente. Respuesta de ejemplo:

{
  "job": {
    "id": 5,
    "filename": "5.wav",
    "text": "Esto puede abarcar desde simples tareas...",
    "status": "processing",
    "attempts": 1,
    "worker_id": "gpu_t4_01",
    "lease_token": "TOKEN_DE_RESERVA",
    "lease_until": 1800000000
  },
  "reference_url": "/api/v1/reference",
  "reference_sha256": "HASH_SHA256",
  "lease_seconds": 1800
}

HTTP 204: no quedan trabajos pendientes. HTTP 409: falta cargar la voz de referencia. El lease_token identifica solamente la reserva del trabajo: no es el mismo token Bearer.

3. Renovar la reserva

Mientras el TTS sintetiza audio, envía heartbeats antes de que venza el tiempo indicado en lease_seconds.

JOB_ID=5
LEASE_TOKEN="PEGA_LEASE_TOKEN"

curl -X POST "$BASE/api/v1/jobs/$JOB_ID/heartbeat" \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d "{\"lease_token\":\"$LEASE_TOKEN\"}"

Si vence, el servidor recupera el trabajo automáticamente. Un token de reserva vencido o ajeno produce HTTP 409.

4. Subir el WAV generado

curl -X POST "$BASE/api/v1/jobs/$JOB_ID/complete" \
  -H "Authorization: Bearer $TOKEN" \
  -F "lease_token=$LEASE_TOKEN" \
  -F "audio=@salida.wav;type=audio/wav"

Si termina correctamente, devuelve {"ok":true}. El servidor almacena el WAV y marca el trabajo como terminado. Si falla la síntesis:

curl -X POST "$BASE/api/v1/jobs/$JOB_ID/fail" \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d "{\"lease_token\":\"$LEASE_TOKEN\",\"error\":\"Fallo de síntesis\"}"

Un error reencola el trabajo si quedan intentos; si no, lo marca como error permanente para revisión.

5. Consultar el progreso

curl -H "Authorization: Bearer $TOKEN" \
  "$BASE/api/v1/stats"

Devuelve total, pending, processing, completed y failed.

Exportación del dataset

El administrador puede descargar desde Descargar ZIP los WAV terminados y su CSV asociado.

Los tokens de cliente solo permiten usar la API de procesamiento; no dan acceso a configuración, exportaciones ni gestión de usuarios.
